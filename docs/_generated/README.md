# Generated reference partials

Hand-authored docs pages tagged `diataxis: reference` should not duplicate
content that already lives in code. The partials in this directory are
emitted by `scripts/docs-reference.ts` from source-of-truth code (JSDoc
tags, package manifests, runtime registries) and transcluded into pages
via the `markdown-it-include` plugin wired into VitePress.

This page is the operator-facing index for `_generated/`. It is itself
hand-authored — it documents the partial schema, the regenerate command,
the drift-detection rules, and the table of contents. The `J-2` frontmatter
gate exempts this page from the "reference page must contain at least one
include directive" rule; everything else under `_generated/` is generated.

## Regenerate

```sh
bun run docs:reference        # write all partials
bun run docs:reference:check  # fail-on-drift; runs as part of `bun run check`
```

A regenerate run reads tagged sources, computes the new partial bytes, and
writes them to disk. Drift-on-`check` means a partial committed to the repo
no longer matches what the generator produces from current source — fix by
running `bun run docs:reference` and committing the result, or by reverting
the change to source.

## Partial schema

Every file under `_generated/` (other than this `README.md`) follows this
header schema, in order:

```md
<!-- AUTO-GENERATED by scripts/docs-reference.ts — do not edit -->
<!-- Source of truth: <space-separated source paths> (<extraction method>) -->
<!-- Generated at: <UTC ISO 8601, second precision> -->
<!-- Generator commit: <git short SHA at run time> -->

<body>
```

- **Line 1** — sentinel; mirrors the per-package README sentinel from
  `scripts/generate-package-readmes.ts`. Hand-edits to a partial will be
  silently overwritten the next time the generator runs.
- **Line 2** — source paths from which the body was extracted, plus a
  short description of the extraction method (e.g. `@hostSurface JSDoc
  tags via ts-morph`).
- **Line 3** — UTC timestamp of the generator run. **Excluded from the
  drift comparison** so an idle regen doesn't appear as drift.
- **Line 4** — short git SHA the generator was invoked at. **Also
  excluded from the drift comparison** (revised from the original plan;
  see "Drift normalization" below). Recorded for audit only.

## Drift normalization

The `--check` mode normalizes both the on-disk bytes and the freshly
regenerated bytes before comparing. The four rules, applied in order:

1. Strip trailing whitespace on every line.
2. Collapse runs of trailing blank lines to a single final `\n`.
3. Drop the `<!-- Generated at: ... -->` line entirely.
4. Drop the `<!-- Generator commit: ... -->` line entirely.

Implemented in `scripts/docs-reference.ts` as
`normalizeForDriftCheck(content: string): string`. Both `--check` and the
generator's idempotency self-test use the same helper.

### Why the SHA line is excluded

The original plan included the SHA line in the drift comparison so a
regenerated partial against the same source tree but a different commit
would fail drift, "forcing a partial regen on every commit and keeping
the SHA honest." That design was self-defeating: committing the
regenerated partial necessarily changes `HEAD`, so any committed-clean
state would immediately fail `docs:reference:check` on the very next
`bun run check`. Reaching steady state is impossible.

The body diff already catches the property the gate is for ("source
changed but nobody regenerated") — extraction inputs that differ from
the partial's body produce a content diff that fails drift correctly.
The SHA line is redundant for drift purposes; its only honest job is
audit, which doesn't need to participate in the gate.

## Adding a new partial

1. Decide source-of-truth: a JSDoc tag (cleanest), a sidecar metadata file,
   or a curated list in the script with a `SOURCE-OF-TRUTH-DEBT` comment
   pointing at the work to migrate it.
2. Add a `PartialSpec` to `PARTIALS` in `scripts/docs-reference.ts`.
3. Run `bun run docs:reference` to emit the file under `_generated/`.
4. In the consuming hand-authored page, replace the section with
   `!!!include(_generated/<partial-name>.md)!!!`.
5. Add a row to the table of contents above.
6. Run `bun run check` and `bun run docs:build` to verify the include
   resolves and the dead-link gate is clean.

## Where this fits

- `AGENTS.md` Working Rules link to this page so contributors find the
  regen path on first contact with `_generated/`.
- `scripts/docs-consistency.ts` enforces the `J-2` frontmatter validator:
  every page in `docs/.manifest.json#handAuthoredPages` carries a
  `diataxis:` tag drawn from a closed set.
- `scripts/docs-reference.ts` imports `ts-morph` only via
  `scripts/lib/package-introspection.ts` — the boundary is enforced by a
  one-line grep gate in `scripts/docs-consistency.ts`.

## Port author rules

Two load-bearing rules for the surviving extractors:

### 1. Output stability via deterministic ordering

Surviving extractors emit either alphabetically-sorted lists
(`getMethodKeyedRegistryEntries` sorts by method name;
`getRuntimeRegistryMatrix` sorts by runtime id) or per-source-module
sections in a fixed order (`getCLISubcommandFlags`, where the consuming
generator iterates a hard-coded list of `ArgSpec` constant names). Never
depend on filesystem walk order or source-declaration order for
byte-stability; the drift gate's normalization handles timestamp + SHA
churn but cannot recover from a reordered list.

### 2. Throw on shape mismatch; do not fall through

Each extractor walks a locked TypeScript shape and throws with a
precise diagnostic if any branch diverges from that shape (for example,
a non-string-literal description, a missing required property, or a
spread of an unknown factory). Silent fallthrough corrupts the partial.
If a future shape change causes throws, fix the source or remove the
partial — do not pile on special cases.
